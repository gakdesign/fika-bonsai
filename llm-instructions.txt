1. Create the ACF layout in the page_builder field group, name it with underscores (e.g. image_text_split)
2. Create template-parts/modules/{layout_slug}.php
3. Create assets/css/modules/{layout_slug}.css
4. Export ACF JSON and commit /acf-json/

[DESIGN TOKENS]
CSS custom properties defined in assets/css/core/additions.css and module CSS files.
The Fika design system uses:

- --accent:       #6E4518   (cinnamon brown — primary brand colour, CTAs, links)
- --accent-hover: #543210   (darker cinnamon — hover state)
- --surface:      #F5F3F2   (warm off-white — panel and card backgrounds)
- --surface-raised: #FFFCFA (cards, modals, sticky bars)
- --ink:          #999999   (body text — light grey, tuned for Glacial Indifference)
- --ink-strong:   rgba(0,0,0,0.7)   (headings, high-emphasis text)
- --muted:        #6B6B6B   (captions, meta, secondary labels)
- --line:         #E6E4E1   (borders, dividers, input outlines)
- Heading font:   Poppins (Google Fonts, weights 400/500/600/700)
- Body font:      Glacial Indifference (self-hosted — see assets/fonts/glacial-indifference/README.md; falls back to system-ui until licensed font files are added)
- Script font:    Caveat (Google Fonts, weight 500 — decorative accents only)
- Border radius:  14px (used consistently across cards, buttons, inputs)
- Max content width: ~72rem / 1152px (class: .max-w)

Note: base.css also carries legacy colour variables from the base theme (--black, --orange, etc.).
Always prefer the Fika design tokens above when writing new module CSS.

[FRONT-END STACK]
- jQuery: available globally via wp_enqueue_script('jquery') — use it for all custom JS
- Bootstrap 5: custom build (bootstrap-custom.min.css + bootstrap.bundle.min.js) — grid, utilities, JS components
- Slick carousel: slick.js + slick.css — for any carousel/slider needs

- CSS pipeline: plain CSS, no preprocessor. Module CSS loaded on-demand by page_builder.php dispatcher.
    - Core styles: assets/css/core/ (base.css, header.css, footer.css, additions.css)
    - Module styles: assets/css/modules/{layout}.css — loaded only when that module appears on a page
- Build system: none. CSS and JS are hand-authored and committed directly. Do NOT minify by hand — use a plugin or pipeline if needed.
- Do NOT hand-edit compiled files. Do NOT introduce npm/webpack unless the project specifically agrees to it.
- SiteMinder IBE widget: enqueued only on is_singular('accommodation') — conditional load, deferred.

[WORDPRESS & PHP GUIDELINES]
- Follow WordPress Coding Standards at all times
- All custom functions prefixed: bonsai_
- No deprecated WordPress functions
- No direct database queries without $wpdb->prepare()
- Output escaping:
    - Plain text: esc_html()
    - Attributes: esc_attr()
    - URLs: esc_url()
    - Rich content: wp_kses_post()
    - Iframes / embeds: bonsai_kses_iframe() — defined in inc/helpers.php — use this, not esc_html() or wp_kses_post()
    - Raw echo get_field() is never acceptable
- Input sanitisation:
    - Text: sanitize_text_field()
    - Email: sanitize_email()
    - Integers: absint()
    - URLs: esc_url_raw()
- Nonces + current_user_can() checks on all forms, AJAX handlers, and admin actions
- ACF patterns:
    - Always check field exists: if ( get_field('field_name') )
    - Repeaters: check have_rows() before looping
    - Flexible Content: use get_row_layout() in a switch
    - Field naming: snake_case, descriptive (e.g. hero_title, hero_background_image)
- DRY, modular, tab-indented code
- Full files only — never deliver fragments unless explicitly asked for a snippet
- No var_dump, die(), console.log, or commented-out blocks in committed code
